# 模块层文件规范（五文件 + 实现级主流基准）

模块层负责"教装配图"：把一组知识点按"方案 / 调用链"串成能跑通的模块（如登录、权限、文件上传）。它是轻量的一等学习单元，只教"怎么穿"，不重复教知识点——链上每个节点回落到知识点层去练。

## 一、目录结构

```
modules/
└── 用户系统/
    ├── 01-方案选型.md      # 几种主流做法 + 原理 + 适用场景 + 选型
    ├── 02-推荐方案实现.md   # 完整可运行规范代码 + 最佳实践 + 常见坑（核心）
    ├── 03-调用链.md        # 数据流 + 执行顺序
    ├── 04-知识点清单.md     # 链上每点 → 指向知识点层目录
    └── 05-综合练习/         # 自己把整条链串一遍（可含 template.js + test.js）
```

模块可嵌套：大模块套子模块。例如"用户系统"下含"认证子模块（登录）"与"授权子模块（权限）"。

## 二、01-方案选型.md（概览级，快速带过）

列出该主题的几种主流方案，各自原理、适用场景、选型建议。例如登录模块：

| 方案 | 原理 | 适用场景 |
|------|------|----------|
| Session | 服务端存状态，客户端持 sessionId | 传统服务端渲染、同源应用 |
| JWT | 无状态、自包含 token | 前后端分离 API、微服务、跨域 |
| OAuth 2.0 | 第三方授权 | 接入微信 / Google 等第三方登录 |

结论：前后端分离选 JWT，并说明为什么。

## 三、02-推荐方案实现.md（实现级，核心）

选定方案后给出**完整、可运行、符合业界规范的代码**，并拆三块：

1. **完整实现**：规范写法，可直接跑（或贴近可跑），结构清晰。
2. **最佳实践**：为什么这样写——分层、命名、错误处理、安全边界、配置外置。
3. **常见坑**：不规范写法 vs 规范写法对照。例如 JWT 场景：token 明文存 `localStorage` 的 XSS 风险、密钥硬编码、`exp` 刷新未处理、无失效机制等。

> 此文件是"实现级"教学正文，深度远高于知识点层的 example.js（后者只聚焦单点最小化）。两层深度不同，互不重复。

## 四、03-调用链.md（数据流）

画出整条链路与数据流向，例如基于某登录模块：

```
① 前端表单 → 发账号密码
② 后端校验通过 → 签发 JWT（含 id / role / perms，设过期）
③ 前端存 token → 后续请求头带 Authorization
④ 后端 auth 中间件 → 校验 JWT + 限流
⑤ 受保护路由 → 再走角色 / 权限点校验
⑥ 通过放行，不通过 403
```

标注每一环"谁先谁后、数据怎么流"。

## 五、04-知识点清单.md（链 → 原子层）

逐环节列出涉及的原子知识点，并指向知识点层目录，便于用户跳去练：

| 链路环节 | 涉及的原子知识点 | 指向 |
|----------|------------------|------|
| ② 签发 | JWT 签发 / 校验、密钥管理 | `library/0xx-JWT` |
| ④ 校验 | 中间件机制、组合 | `library/0xx-中间件` |
| ⑤ 授权 | RBAC、权限点、审核流 | `library/0xx-权限点` |

## 六、05-综合练习（串整条链）

把整条链串起来写一遍，可落盘 `template.js` + `test.js`（套用知识点层规范）。目的是验证"零件都会 ≠ 会装模块"。

## 七、教学基准铁律（贯穿模块层）

- **调研主流为权威**：实现前先确认当前业界推荐做法，不凭训练时的固有知识硬写。
- **项目代码只是线索 / 对照**：若用户贴了自家项目，先指出其做法，再对照主流方案评价规范与否，而不是把项目写法当标准。
- **深度 = 实现级**：选型对比可概览，但推荐实现必须完整、规范、含最佳实践与坑。

## 八、与知识点层引擎的分工

引擎 `scripts/trainer.mjs` 只负责**知识点层**（`library/`）的 SM-2 进度与选题。模块层（`modules/`）的"读"（01~04：方案选型 / 实现 / 调用链 / 清单）由 AI 按本文档顺序带过，不需要间隔复习；模块层的"练"（05-综合练习）若落成了 `template.js` + `test.js`，本质就是知识点层题，仍走 `trainer.mjs` 的 `review-next` 推进。模块层自身不重复造一套进度引擎。注意：引擎 `scan` 只扫描 `library/`（平铺编号目录），不扫 `modules/`——模块综合练习若要被引擎自动跟踪（进 SM-2 / 选题），需放入 `library/` 目录；留在 `modules/` 内则只能由 AI 手动 `review-next` 推进。
