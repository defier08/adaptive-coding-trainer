# 三场景闭环与选题优先级

本 skill 的三个使用场景不是三套独立系统，而是同一闭环的三段：二、三是"输入"（发现该练什么），一是"输出"（沉淀成体系）。

## 一、场景定义

### 场景二：项目驱动（入口）
- **触发**：用户贴出 / 指向真实项目代码（如 luo3 的登录、CORS、文件遍历）。
- **做法**：从代码里挖出涉及的知识点 → 生成或定位对应知识点 / 模块题目。
- **价值**：题目与正在写的代码直接挂钩，学会马上能用，不是凭空刷算法。

### 场景三：卡点驱动（入口）
- **触发**：用户写项目时报错 / 写错 / 卡住。
- **做法**：把踩坑处沉淀成针对性题目（并补进该知识点的 `@prereq` 依赖图）。
- **价值**：事后精准补强，错题反哺依赖图。

### 场景一：系统化学习（体系 / 输出）
- **触发**：二、三积累的知识点越来越多，依赖图把它们连成网。
- **做法**：引擎按依赖图（prereq 拓扑）推进——`pick` 的新题阶段优先推"前置已满足"的知识点，若全部被前置卡住则返回 `blocked_by` 暴露薄弱前置；`graph` 命令可查看整张依赖图与各点掌握状态。
- **价值**：零散点自然长成体系，缺啥补啥。

## 二、闭环串联

```
用户在写项目
   ├─ 碰到一段代码 / 一个知识点  ──→ 场景二：项目驱动出题
   └─ 报错 / 写错 / 卡住         ──→ 场景三：卡点驱动出题
                    │
                    ▼
        题目落库到 `library/`（不进项目目录，带元数据 @kp/@tags/@difficulty/@prereq）
                    │
                    ▼
        依赖图自动串成体系 → 暴露薄弱前置知识点
                    │
                    ▼
        场景一：系统化学习自然浮现（缺啥补啥、薄弱点反复练）
```

## 三、选题优先级（多入口冲突时的裁决规则）

当三个入口同时有候选时，按固定优先级裁决，避免 AI 与多入口打架：

```
卡点（刚踩的坑）  >  项目驱动（正在做的）  >  系统化（依赖图推进）
```

- 最高：用户**当前卡住 / 刚报错**的点，立即针对它出题或出变体。
- 其次：用户**正在进行的项目**里挖出的知识点。
- 最低：依赖图推进的常规复习 / 新知识点。

此优先级由引擎真正执行：场景二/三触发时，先把题目落盘到 `library/`（不进项目目录），再用 `enqueue --kp <名> --source project|stuck` 把知识点加入选题队列；`pick` 会先消费队列（stuck 优先于 project，选中即消费，未完成需重新 enqueue），队列空后再回落到 SM-2 到期复习 / 新题（新题按依赖图拓扑 + 难度由易到难推进）。用户**显式指定主题**时例外——以用户指定为准。
